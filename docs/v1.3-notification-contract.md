## 三、API（挂 /api/v1/notifications）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/notifications?user=:address` | 列出某用户通知（未读优先、created_at 降序） |
| PATCH | `/notifications/:id/read` | 标记单条已读，返回 `NotificationDto` |
| POST | `/notifications/read-all` | 全部已读（body: `{ userAddress }`），返回 `{ updated: number }` |
| GET | `/notifications/unread-count?user=:address` | 未读数（供顶栏角标），返回 `{ count: number }` |

### 3.1 DTO（camelCase）

```ts
interface NotificationDto {
  id: string;
  userAddress: string;
  type: string;             // 当前恒为 "price_alert_triggered"
  title: string;
  body: string;
  alertId: string | null;
  tokenAddress: string | null;
  read: boolean;
  createdAt: string;        // ISO 字符串
}

interface UnreadCountDto {
  count: number;
}
```

### 3.2 排序规则

- `GET /notifications` 返回 `NotificationDto[]`，排序：`read` 升序（未读在前）+ `created_at` 降序。

## 四、触发落库（接线点，关键）

`AlertsService.checkPriceAlerts` 命中提醒（`status` 置 `triggered`）时，调用 `NotificationsService.createNotification` 落一条通知：

- `type = "price_alert_triggered"`
- `title` 形如 `WETH 价格提醒已触发`
- `body` 形如 `WETH 现价已 ≥ 2500，触发你的价格提醒`
- `alert_id = alert.id`、`token_address = alert.token_address`
- **幂等**：同一 alert 从 active→triggered 只落一次（`checkPriceAlerts` 里命中才更新 status 为 triggered，天然只触发一次；但需防「重复跑 check」重复落——建议在落通知前判断该 alert 是否已处于 triggered 且已落过通知，或依赖 status 更新返回值判断）。

> 依赖方向：`AlertsModule` import `NotificationsModule`（单向 Alerts → Notifications，无循环）。由 V1.3-2a 工程师接线。

## 五、推送抽象（可插拔通知渠道，V1.3-3a）

- 定义 `NotificationProvider` 接口（`apps/api/src/modules/notifications/notification-provider.interface.ts`）：

```ts
export interface NotificationProvider {
  readonly name: string; // 'in_app' | 'email' | 'webhook'
  send(notification: NotificationDto): Promise<void>;
}
```

- 内置 `InAppProvider`：写 Notification 表（即模块 2 的地基，天然实现）。
- `EmailProvider` / `WebhookProvider`：V1.3 只留接口 + 配置占位，**不实现真实发送**（本机代理受限 + 需第三方 key）。未接入时降级为「站内通知 + 记录渠道未接入日志」，不报错。
- 分派逻辑：`notifyMethod` 为 `in_app` 走 InAppProvider；为 `email`/`webhook` 时，V1.3 先降级走 InAppProvider 并 warn「渠道未接入」。

> 抽象层可放 `notifications/` 目录下，由 V1.3-3a 工程师在 V1.3-2a 基础上叠加。
