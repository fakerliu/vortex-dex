## 一、V1.2 定位与范围结论

V1.2 聚焦**「基础体验补全」**：只做**无合约依赖**的 P1 功能，不引入自有合约、不引入 keeper。

### 纳入 V1.2（2 个模块）

| 模块 | PRD 编号 | 说明 |
|------|---------|------|
| **价格提醒（Price Alerts）** | MODULE 14（Alerts） | 用户对某 token 设定价格阈值提醒 |
| **用户偏好（Preferences）** | MODULE 14（Preferences） | 默认滑点、默认链、代币收藏、通知偏好 |

### 明确推后（V1.3+ 专项，不在 V1.2）

| 模块 | PRD 编号 | 推后原因 |
|------|---------|---------|
| Limit Order | MODULE 10 | 需自有合约或链下 keeper，架构级决策，需专项设计+安全审计 |
| DCA | MODULE 11 | 同上，与 Limit Order 共享 keeper/合约基础设施 |
| Cross-chain | MODULE 12 | 需桥接/跨链协议，工程量最大，且与「Base 单链定位」需先产品论证 |

> 推后依据：V1.0/V1.1 一直遵循「非托管、复用官方 Router、无自有合约」原则（见 `contracts/README.md`，目前 0 个 .sol、Foundry 未装）。合约类功能是**架构级新增**，不应在「基础体验补全」版本仓促引入，需在明确产品需求 + 充分安全设计后单独开 V1.3 专项。

## 二、模块 1：价格提醒（Price Alerts）

### 2.1 与现有「系统告警」的区别（关键，避免混淆）

现有 `alert_rules` / `anomaly_events` / `alert_notifications` 是**「系统异常告警」**（内部监控：错误率、区块延迟、报价延迟等，面向运维）。V1.2 的「价格提醒」是**「用户价格提醒」**（面向用户：某 token 涨到/跌到某价时通知我），是完全不同的领域，**不复用**现有三张表，需新建独立模型。

### 2.2 功能定义

- 用户可对某 token 设置价格提醒：`token + 链 + 条件（≥ 或 ≤）+ 目标价 + 通知方式`
- 提醒触发后一次性通知（或按用户设置重复/静默）
- 通知方式：站内（优先，无外部依赖）+ 可选邮箱/Webhook（后续接通知渠道）

### 2.3 数据模型（新增，Prisma）

```prisma
model PriceAlert {
  id            String   @id @default(cuid())
  user_address  String   // 小写规范化
  chain_id      Int
  token_address String   // 小写规范化
  symbol        String   // 冗余，方便展示
  condition     String   // gte / lte（涨到/跌到）
  target_price  Decimal  @db.Decimal(78, 18)  // 目标价（USD）
  notify_method String   @default("in_app")   // in_app / email / webhook
  status        String   @default("active")   // active / triggered / paused
  triggered_at  DateTime?
  created_at    DateTime @default(now())
  updated_at    DateTime @updatedAt

  @@index([user_address])
  @@index([chain_id, token_address])
  @@index([status])
  @@map("price_alerts")
}
```

### 2.4 API（挂 /api/v1）

- `POST /alerts` — 创建提醒
- `GET /alerts?user=:address` — 列出某用户提醒
- `PATCH /alerts/:id` — 更新/暂停/启用
- `DELETE /alerts/:id` — 删除

### 2.5 触发机制（无 keeper，轻量）

- **被动触发**：价格提醒在「市场快照落库」（`MarketService.persistSnapshot`）或「用户查询」时惰性检查，而非独立常驻进程。
- 复用现有 `market_snapshots` 历史快照（V1.1 已改追加式），比对最新价 vs 目标价，命中则标记 `triggered` + 生成站内通知。
- 若需要「准实时」，后续可加定时任务（复用 automation 或 cron），V1.2 先做惰性检查。

## 三、模块 2：用户偏好（Preferences）

### 3.1 功能定义

- 默认滑点（defaultSlippageBps）、默认链（defaultChainId）、默认交易 deadline
- 代币收藏（favorites，用于 Swap 页快速选择）
- 通知偏好（是否开启价格提醒、通知方式）

### 3.2 数据模型（新增，Prisma）

```prisma
model UserPreference {
  id                   String   @id @default(cuid())
  user_address         String   @unique  // 小写规范化
  default_slippage_bps Int      @default(50)
  default_chain_id     Int      @default(8453)
  default_deadline_sec Int      @default(1200)
  notify_alerts        Boolean  @default(true)
  favorite_tokens      String?  // JSON 数组：[{chainId, address, symbol}]
  created_at           DateTime @default(now())
  updated_at           DateTime @updatedAt

  @@map("user_preferences")
}
```

### 3.3 API（挂 /api/v1）

- `GET /preferences/:address` — 读取偏好（无则返回默认值）
- `PUT /preferences/:address` — upsert 偏好
- `POST /preferences/:address/favorites` — 加收藏
- `DELETE /preferences/:address/favorites/:token` — 移除收藏

### 3.4 与现有系统的集成点

- Swap 页读取 `defaultSlippageBps` / `defaultChainId` 作为初始值
- Swap 页代币选择器展示 favorites
- 价格提醒模块读取 `notify_alerts` / `notify_method`

## 七、遗留与后续（V1.3+ 候选）

- **Limit Order / DCA**：需先做「自有合约 vs 链下 keeper」架构决策 + 安全审计，建议 V1.3 开专项
- **Cross-chain**：需产品论证 Base 单链定位是否扩展
- **拆单性能**（V1.1 遗留）：极严阈值 + 大额的二分慢路径，可用「classic 池解析式免二分」或「异步化」根治，按需排期
- **通知渠道**：价格提醒的邮箱/Webhook 通知，需接第三方通知服务，V1.2 先做站内
