# V1.1-3 拆单路由（Split Order Routing）共享契约

> 本文档是拆单路由前后端并行派工的唯一依据。前后端必须严格按此契约实现，任何字段/路径/语义改动须先更新本文档并同步对方。
>
> 状态：已定稿（team lead 2026-11-05）

---

## 1. 目标与触发

大额订单（tokenIn → tokenOut）在**同时满足**以下两个条件时，自动拆分为 N 条独立子单：

1. **金额阈值**：`amountIn`（链上原始大整数）≥ `SPLIT_MIN_AMOUNT`（默认值见 §5 配置，按 token decimals 判定）；且
2. **价格影响阈值**：单一路径最优报价的 `priceImpact`（十进制字符串，如 "0.0123" 表示 1.23%）≥ `SPLIT_PRICE_IMPACT_THRESHOLD`（默认 "0.01"）。

不满足时回退为现有单路径 `prepare` 流程（行为不变）。

## 2. 数据模型（schema.prisma 新增）

### 2.1 SplitOrder（母单）

```prisma
model SplitOrder {
  id           String   @id @default(cuid())
  user_address String   // 小写规范化
  chain_id     Int
  token_in     String
  token_out    String
  amount_in    Decimal  @db.Decimal(78, 0)  // 母单总输入（原始大整数）
  status       String   // pending / partial / completed / failed / cancelled
  child_count  Int      // 子单数量
  intent_id    String?
  created_at   DateTime @default(now())
  updated_at   DateTime @updatedAt

  children SplitChild[]

  @@index([user_address])
  @@index([intent_id])
  @@map("split_orders")
}
```

### 2.2 SplitChild（子单，1:1 关联 Swap）

```prisma
model SplitChild {
  id             String   @id @default(cuid())
  split_order_id String   // FK -> SplitOrder.id
  swap_id        String?  // FK -> swaps.id（子单广播回写后填充）
  pool_address   String   // 该子单走哪个池
  protocol_type  String   // aerodrome_classic / aerodrome_cl / uniswap_v3
  amount_in      Decimal  @db.Decimal(78, 0)  // 该子单输入（原始大整数）
  amount_out     Decimal  @db.Decimal(78, 0)  // 该子单期望输出
  price_impact   Decimal? @db.Decimal(78, 18) // 该子单独立 priceImpact
  order_index    Int      // 子单序号（1..N）
  status         String   // pending / confirmed / failed
  created_at     DateTime @default(now())

  splitOrder SplitOrder @relation(fields: [split_order_id], references: [id])
  swap       Swap?      @relation(fields: [swap_id], references: [id])

  @@index([split_order_id])
  @@index([swap_id])
  @@map("split_children")
}
```

> 说明：`swap_id` 可空——子单在 `prepare` 阶段已生成 calldata，但 `swap` 记录在钱包广播后经 `submit` 才落库，此时回填 `split_children.swap_id`。

## 3. API 契约

统一前缀 `/api/v1`，响应信封沿用现有 `{ code, message, data, meta }`（transform.interceptor）。

### 3.1 POST `/api/v1/swaps/split/prepare`

**请求体**（复用 PrepareSwapRequestDto 语义，去掉单路径专属字段）：

```jsonc
{
  "chainId": 8453,
  "userAddress": "0x...",
  "tokenIn": "0x...",
  "tokenOut": "0x...",
  "amountIn": "100000000000000000000",   // 原始大整数字符串
  "slippageBps": 50,
  "intentId": "optional",
  "maxSplits": 5                          // 可选，最大拆分数，默认 5
}
```

**响应 data**：

```jsonc
{
  "splitOrderId": "cuid",
  "chainId": 8453,
  "userAddress": "0x...",
  "tokenIn": "0x...",
  "tokenOut": "0x...",
  "amountIn": "100000000000000000000",
  "amountOutTotal": "95000000",           // 各子单 amountOut 之和（原始大整数）
  "priceImpactAggregated": "0.008",       // 拆分后整体价格影响（加权/合成，十进制字符串）
  "splits": [
    {
      "index": 1,
      "poolAddress": "0x...",
      "protocolType": "aerodrome_classic",
      "amountIn": "60000000000000000000",
      "amountOut": "57000000",
      "priceImpact": "0.007",
      // 下面是每个子单独立执行所需，复用 PrepareSwapResponseDto.transaction/approval 语义
      "minimumReceived": "56500000",
      "deadline": 1730000000,
      "spender": "0x...",
      "transaction": { "to": "0x...", "value": "0", "data": "0x...", "functionName": "...", "selector": "...", "gasLimit": "..." }
    }
  ],
  // 聚合授权：按 spender 分组，每个不同 spender 一条 approve（前端先做一次即可）
  "approvals": [
    { "token": "0x...", "spender": "0x...", "amount": "100000000000000000000", "needed": true, "data": "0x...", "functionName": "approve", "selector": "..." }
  ],
  "quoteTimestamp": "2026-11-05T...",
  "notes": ["已拆分为 2 条子单"]
}
```

**关键语义**：
- `approvals` 是**聚合授权**，不是每子单一条。按 `spender`（Router 地址）分组：同一 spender 的子单 amountIn 求和作为授权额度。前端**每个不同 spender 只 approve 一次**。
- 每个子单的 `transaction.data` 是独立 calldata（单协议单跳，无 mixed 问题），前端逐条签名广播。

### 3.2 POST `/api/v1/swaps/split/:splitOrderId/submit-child`

每广播成功一条子单，回写一次。

**请求体**：

```jsonc
{
  "childIndex": 1,                 // 对应 split.prepare 返回的 index
  "txHash": "0x...",               // 该子单已广播的交易哈希
  "amountOut": "57000000"          // 期望输出（占位，链上确认后由 indexer 更新）
}
```

**响应 data**：`{ splitOrderId, childIndex, swapId, status }`

### 3.3 GET `/api/v1/swaps/split/:splitOrderId`

母单详情 + 子单进度。

**响应 data**：

```jsonc
{
  "splitOrderId": "cuid",
  "status": "partial",             // pending / partial / completed / failed / cancelled
  "childCount": 2,
  "amountIn": "100000000000000000000",
  "children": [
    { "index": 1, "poolAddress": "0x...", "protocolType": "...", "amountIn": "...", "status": "confirmed", "swapId": "...", "txHash": "0x..." },
    { "index": 2, "...", "status": "pending", "swapId": null, "txHash": null }
  ]
}
```

## 4. 拆分算法（后端 SplitService）

1. **拿全量候选**：`DexPoolService.discoverPools` + `quotePair`（8453）/ `discoverUniswapV3Pools` + `quoteUniswapV3Pair`（84532），得到所有池的 `PoolQuoteCandidate[]`，每个含独立 `quote.priceImpact` 与 `quote.amountOut`。
2. **判定是否拆分**：若候选数 ≤ 1，或最优单路径 priceImpact < 阈值，则不拆（走单路径 prepare）。
3. **金额分配**（贪心 + 二分，纯 BigInt）：
   - 目标：把总 `amountIn` 分配到 N 个池，使每个子单 priceImpact 尽量压到阈值以下，且总 `amountOut` 最大。
   - 对每个候选池，用不同 `amountIn` 反复 `adapter.getQuote`（或 `quotePair` 单池重报）二分找「该池在不超 priceImpact 阈值前提下的最大可承接金额」。
   - 贪心填充：按 amountOut 效率（单位 amountIn 产出）降序，优先填效率高的池；剩余金额继续填下一池，直到分配完或达到 `maxSplits`。
   - 若无法在不超阈值前提下分完（流动性不足），最后一池承接剩余金额并如实标注其 priceImpact（可能超标），在 `notes` 中提示。
4. **逐子单构造执行**：对每个子单调 `swapService.prepare({ ..., route: { tokenPath:[in,out], poolPath:[pool], protocolPath:[proto] }, amountIn: childAmountIn })`，取回该子单的 `transaction`/`spender`/`minimumReceived`/`deadline`。
5. **聚合授权**：按 `spender` 分组，同组子单 amountIn 求和 → 生成 `approvals[]`（额度=该 spender 名下的和，needed = 当前 allowance < 该和）。
6. **落库**：创建 `SplitOrder` + N 个 `SplitChild`（swap_id 暂空）。

> 复用边界（已调研确认）：执行层**复用 `prepare(显式单跳 route)`**，无需新合约；`quotePair` 已是「多候选 + 各自 priceImpact」现成入口；`RouteCandidate` 仅作候选来源引用，**不复用为拆单存储**。

## 5. 配置（env，后端读取，均有默认值）

| 变量 | 默认 | 含义 |
|------|------|------|
| `SPLIT_MIN_AMOUNT_USD` | "100000" | 触发拆分的最小金额（USD，十进制字符串） |
| `SPLIT_PRICE_IMPACT_THRESHOLD` | "0.01" | 单路径 priceImpact 触发阈值（1% = "0.01"） |
| `SPLIT_MAX_CHILDREN` | "5" | 最大拆分数 |

> 注：`SPLIT_MIN_AMOUNT_USD` 需将 amountIn 换算为 USD（复用 MarketService.getTokenPrice 的链上推导价格），换算失败则跳过金额条件（仅按 priceImpact 判定）。

## 6. 前端契约（apps/web）

- **触发提示**：调 `split/prepare` 前，前端先按金额/价格影响预估是否可能触发拆分（或直接由后端在 prepare 返回里标记 `suggestSplit: true`）。为降低往返，采用：前端先调普通 `prepare`，若响应 `priceImpact` ≥ 阈值且金额 ≥ 阈值，前端弹「建议拆分」提示，用户确认后调 `split/prepare`。
- **母单预览**：拿到 `split/prepare` 响应，展示母单总金额 + N 子单（各池/协议/金额/priceImpact/期望输出）+ 聚合 approve 提示。
- **授权**：遍历 `approvals[]`，每个不同 spender 先签名一条 approve（额度为聚合值）。
- **广播**：遍历 `splits[]`，逐条签名广播 `transaction`，每成功一条调 `split/:id/submit-child` 回写。
- **进度**：轮询或 refetch `split/:id` 展示子单状态（pending/confirmed/failed）。

## 7. 验收标准

- 后端：拆分算法单测（金额分配正确性、priceImpact 阈值边界、单池不足回退、maxSplits 上限）+ `split/prepare`/`submit-child`/`GET` 三接口 e2e；`tsc --noEmit` 0 错误；全量 jest 通过。
- 前端：拆分提示→预览→聚合授权→逐条广播→进度追踪的完整链路；typecheck 通过；`next build` 通过。
- 数据一致性：子单全部 confirmed → 母单 completed；任一 failed 且其余 completed → 母单 partial；全部 failed → failed。
