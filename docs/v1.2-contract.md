## 一、总则

- 金额铁律：价格用 `Decimal(78,18)` 定点、十进制字符串；禁 Float。
- 地址铁律：EVM 地址统一小写规范化。
- 响应信封：沿用全局 `{ code, message, data, meta }`（transform.interceptor），后端 controller 直接 return data，不手包信封。

## 二、模块 1：价格提醒（Price Alerts）

### 2.1 数据模型（schema.prisma 新增）

```prisma
model PriceAlert {
  id            String    @id @default(cuid())
  user_address  String    // 小写规范化
  chain_id      Int
  token_address String    // 小写规范化
  symbol        String    // 冗余，方便展示（如 "WETH"）
  condition     String    // gte / lte（涨到/跌到）
  target_price  Decimal   @db.Decimal(78, 18)  // 目标价（USD）
  notify_method String    @default("in_app")   // in_app / email / webhook
  status        String    @default("active")   // active / triggered / paused
  triggered_at  DateTime?
  created_at    DateTime  @default(now())
  updated_at    DateTime  @updatedAt

  @@index([user_address])
  @@index([chain_id, token_address])
  @@index([status])
  @@map("price_alerts")
}
```

### 2.2 API（挂 /api/v1/alerts，新模块 alerts）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/alerts` | 创建提醒 |
| GET | `/alerts?user=:address` | 列出某用户提醒（按 created_at 降序） |
| PATCH | `/alerts/:id` | 更新（condition/target_price/notify_method/status） |
| DELETE | `/alerts/:id` | 删除 |
| POST | `/alerts/check` | 手动触发一次惰性检查（触发所有 active 提醒，命中则置 triggered + 返回命中列表） |

### 2.3 请求/响应 DTO（camelCase）

```ts
// 创建/更新请求体
interface CreateAlertRequestDto {
  userAddress: string;
  chainId: number;
  tokenAddress: string;
  symbol: string;
  condition: 'gte' | 'lte';
  targetPrice: string;      // 十进制字符串，如 "2500"
  notifyMethod?: 'in_app' | 'email' | 'webhook'; // 默认 in_app
}

// 返回的 alert 条目
interface PriceAlertDto {
  id: string;
  userAddress: string;
  chainId: number;
  tokenAddress: string;
  symbol: string;
  condition: 'gte' | 'lte';
  targetPrice: string;      // 十进制字符串
  notifyMethod: string;
  status: 'active' | 'triggered' | 'paused';
  triggeredAt: string | null; // ISO 字符串
  createdAt: string;
}

// POST /alerts/check 返回
interface CheckAlertsResult {
  checked: number;           // 本次检查的 active 提醒数
  triggered: PriceAlertDto[]; // 命中的提醒
}
```

### 2.4 触发机制（无 keeper，惰性）

- **核心方法**：`AlertsService.checkPriceAlerts(): Promise<CheckAlertsResult>`
  - 读所有 `status=active` 的提醒；
  - 对每个提醒，读 `market_snapshots` 表该 (chain_id, token_address) 的最新一条 `price_usd`（复用 V1.1 追加式历史快照，`orderBy created_at desc` 取第一）；
  - 无快照或 price_usd 为 null → 跳过（不触发）；
  - `condition=gte` 且 `latest >= target` → 命中；`condition=lte` 且 `latest <= target` → 命中；
  - 命中 → `status=triggered` + `triggered_at=now`；
  - 用 BigInt 定点比较（`parseDecimal`，18 位），禁 Float。
- **触发时机**：V1.2 先做「手动/接口触发」`POST /alerts/check` + 「快照落库后惰性触发」（见 2.5），不做独立常驻进程。
- 站内通知：命中即 `status=triggered`，前端 `/alerts` 页高亮展示「已触发」的提醒。V1.2 不接 email/webhook 实际发送（字段预留）。

### 2.5 与 Market 模块的关系（避免循环依赖，关键）

- **Alerts 模块只依赖 Prisma**（读 `market_snapshots` + `price_alerts` 表），**不注入 MarketService**，避免循环依赖。
- 惰性触发接线：在 `MarketService.persistSnapshot` 落库**之后**，若 Alerts 模块已注入，调用 `alertsService.checkPriceAlerts()`。
  - 实现方式：Market 模块 `imports: [AlertsModule]`，`MarketService` 构造函数注入 `AlertsService`（AlertsModule 需 `exports: [AlertsService]`）。
  - 由于 AlertsService 不依赖 MarketService，**无循环依赖**（单向：Market → Alerts）。
  - `checkPriceAlerts` 需幂等、失败静默（try/catch + logger.warn，不影响快照落库主流程）。
  - 注意：`getMarketSnapshot` 是逐 token 落库，若每 token 都触发一次全量检查会重复。**折中**：`checkPriceAlerts` 内部按 `updated_at` 做节流（如最近 30s 已检查过则跳过），或只在 `getMarketSnapshot` 全部落库后统一触发一次（推荐后者，在 `getMarketSnapshot` 的 for 循环结束后调一次）。

## 三、模块 2：用户偏好（Preferences）

### 3.1 数据模型（schema.prisma 新增）

```prisma
model UserPreference {
  id                   String   @id @default(cuid())
  user_address         String   @unique  // 小写规范化
  default_slippage_bps Int      @default(50)
  default_chain_id     Int      @default(8453)
  default_deadline_sec Int      @default(1200)
  notify_alerts        Boolean  @default(true)
  favorite_tokens      String?  // JSON 数组：[{chainId, address, symbol}]
  created_at           DateTime @default(now())
  updated_at           DateTime @updatedAt

  @@map("user_preferences")
}
```

### 3.2 API（挂 /api/v1/preferences，新模块 preferences）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/preferences/:address` | 读取偏好（无则返回默认值，不落库） |
| PUT | `/preferences/:address` | upsert 偏好（body 为部分字段，未传的用默认/保留） |
| POST | `/preferences/:address/favorites` | 加收藏（body: `{chainId, address, symbol}`，去重） |
| DELETE | `/preferences/:address/favorites/:chainId/:tokenAddress` | 移除收藏（按 chainId+address 匹配，chainId 为 path 参数） |

### 3.3 DTO（camelCase）

```ts
interface UserPreferenceDto {
  userAddress: string;
  defaultSlippageBps: number;   // 默认 50
  defaultChainId: number;        // 默认 8453
  defaultDeadlineSec: number;    // 默认 1200
  notifyAlerts: boolean;         // 默认 true
  favoriteTokens: Array<{ chainId: number; address: string; symbol: string }>; // 默认 []
}

// PUT body（全部可选，部分更新）
interface UpdatePreferenceRequestDto {
  defaultSlippageBps?: number;
  defaultChainId?: number;
  defaultDeadlineSec?: number;
  notifyAlerts?: boolean;
}
```

### 3.4 语义

- `GET` 无记录时返回全默认值（不落库，幂等）。
- `PUT` upsert：有记录则更新传入字段，无则创建（缺省字段用默认值）。
- 收藏增删：`favorite_tokens` 是 JSON 字符串，后端读→改→写，按 `chainId+address` 去重（跨链同地址代币如 WETH 在 Base/Sepolia 互不覆盖、互不串扰）。
- `default_slippage_bps` 校验 0~10000 整数；`default_chain_id` 校验 8453/84532。

## 四、前端契约（apps/web）

### 4.1 页面

- `/alerts`：价格提醒列表（active/triggered/paused 分组）+ 创建/编辑/删除 + 「已触发」高亮。
- `/settings`：默认滑点/链/deadline 表单 + 通知开关 + 收藏管理（增删）。

### 4.2 集成

- Swap 页：初始滑点读 `GET /preferences/:address` 的 `defaultSlippageBps`（无钱包连接时用默认 50）。
- Swap 页代币选择器：展示 `favoriteTokens`，支持一键收藏/取消。
- 创建提醒入口：可从 Token Detail 页（`/token/[address]`）加「设价格提醒」按钮，或 `/alerts` 页内手动填 token。

### 4.3 服务层（apps/web/src/services/）

- `alerts.ts`：`createAlert` / `listAlerts` / `updateAlert` / `deleteAlert` / `checkAlerts`
- `preferences.ts`：`getPreference` / `updatePreference` / `addFavorite` / `removeFavorite`
  - `removeFavorite(address, chainId, tokenAddress)`：chainId 为 path 参数，与收藏项一一对应。

## 五、验收标准

- 后端：`tsc --noEmit` 0 错误；全量 jest 通过（新增 alerts 单测 ≥4、preferences 单测 ≥4）。
- 前端：typecheck + `next build` 通过。
- 功能链路：
  1. 创建提醒（WETH ≥ 2500）→ 手动 `POST /alerts/check` 或快照落库 → 若最新价 ≥ 2500 则 `status=triggered`。
  2. `PUT /preferences/:address` upsert 默认滑点 → `GET` 返回该值 → Swap 页读它。
  3. 收藏增删去重正确。
